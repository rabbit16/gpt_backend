## 三、签名规则

1. 取全部参数，去掉 `hash`、`null`、空字符串（数值 `0` 要保留）。
2. 按参数名 ASCII 升序，拼成 `key1=value1&key2=value2`。
3. 末尾**直接**追加 APPSECRET，不加任何连接符。
4. MD5 取 32 位小写。

下单响应和回调通知都要用同一算法验签。验签必须兼容平台新增字段，
因此实现里是遍历全部字段，而不是固定字段列表。

## 四、流程

### 下单

`POST /apiAI/user/xunhupay/pay`

- `pay_type=auto`：按 UA 分流，手机走 H5（返回 `url`），PC 走扫码（返回 `url_qrcode`）。
- `pay_type=h5` / `qrcode`：强制指定。
- 订单号 `{function_code}-{user_id}-{13位毫秒时间戳}`，与微信 v3、蓝兔一致。
- 下单金额写入 Redis（`xunhupay:amount:<订单号>`，7 天），供回调核对。
- **金额只接受大于 0 的整数元**，小数/0 直接返回 400。

### 入账规则

`utils/pay_util/xunhupay/settle.py`：

- 系统没有会员档位，`User.token` 就是人民币余额。
- 用户充多少就加多少（充 26 元，余额 +26），不做任何权益换算。
- 不经过旧的 `add_num_by_money`，避免历史会员逻辑干扰。

### 回调

`POST /apiAI/user/xunhupay/notify`，form 表单。

| 字段 | 说明 |
| --- | --- |
| `trade_order_id` | 商户订单号 |
| `total_fee` | 实付金额（元） |
| `transaction_id` | 平台交易号 |
| `open_order_id` | 虎皮椒内部订单号 |
| `status` | `OD` 已支付、`CD` 已退款、`RD` 退款中、`UD` 退款失败 |
| `hash` | 签名 |

处理规则：

- 验签失败 → 返回 `fail`，不入账。
- `status != OD` → 返回 `success`，不入账（本期不做退款）。
- 金额与下单记录不一致 → 返回 `fail`。
- 入账成功或重复回调 → 返回纯文本 `success`；业务失败 → `fail`，由平台重试。

### 查单

`GET /apiAI/user/xunhupay/query/{outTradeNo}`，已入账直接读缓存，
否则调用虎皮椒查询接口。状态值与回调一致（`OD`/`WP`/`CD`）。

## 五、联调清单

1. `.env` 填好 `XUNHUPAY_APPID` / `XUNHUPAY_APPSECRET`。
2. 启动后访问 `/apiAI/user/xunhupay/status`，确认 `configured=true`。
3. 下单 1 元，确认返回 `url` 或 `url_qrcode`。
4. 扫码/跳转支付，观察日志是否收到回调且入账成功。
5. 用 `/xunhupay/query/<订单号>` 复核 `paid=true`。

> 本地回调需要公网地址，可用内网穿透把同一路径映射到本地端口。
