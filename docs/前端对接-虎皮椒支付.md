# 前端对接说明：虎皮椒支付

> 本次接入 `/xunhupay/*`（虎皮椒）通道。**前端只需对接下面三个接口**，
> 不要使用旧的 `/pay_rabbit`，也无需对接 `/wxpay/*`。

## 一、基本信息

| 项 | 值 |
| --- | --- |
| 接口前缀 | `/apiAI/user` |
| 鉴权方式 | 请求头 `token: <登录 token>`（除 `notify`、`status` 外都需要） |
| 金额单位 | **元**，必须是**正整数**，不接受小数 |
| 返回格式 | JSON，`code` 为**字符串**，`"0"` 表示成功 |

统一响应结构：

```json
{ "code": "0", "codeMsg": "成功", "data": "" }
```

---

## 二、接口一：下单

```
POST /apiAI/user/xunhupay/pay
Content-Type: application/json
token: <登录 token>
```

### 请求参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `userId` | int | 是 | 当前登录用户 id |
| `money` | int | 是 | 金额（元），**必须是大于 0 的整数**，如 1 / 26 / 50；传 1.5 会被拒绝 |
| `function_code` | string | 是 | 功能编码，用于订单号前缀，固定传 `chatGpt` 即可 |
| `pay_type` | string | 否 | `auto`（默认）/ `h5` / `qrcode` |
| `description` | string | 否 | 订单标题，最多 42 个汉字，留空用默认 |

`pay_type` 说明：

- `auto`：由后端按 User-Agent 判断。手机 → `h5`，电脑 → `qrcode`。**推荐用这个。**
- `h5`：强制手机跳转链接。
- `qrcode`：强制 PC 二维码。

### 请求示例

```json
{
  "userId": 1,
  "money": 50,
  "function_code": "chatGpt",
  "pay_type": "auto"
}
```

### 成功响应

```json
{
  "code": "0",
  "codeMsg": "成功",
  "data": "",
  "outTradeNo": "chatGpt-1-1729500000000",
  "payType": "qrcode",
  "payUrl": "https://api.xunhupay.com/.../qrcode.png",
  "userId": 1
}
```

| 字段 | 说明 |
| --- | --- |
| `outTradeNo` | 商户订单号，**必须保存**，查单时要用 |
| `payType` | 实际使用的通道：`qrcode` 或 `h5` |
| `payUrl` | `qrcode` 时是**二维码图片地址**；`h5` 时是**跳转链接** |

### 前端处理

```js
const { outTradeNo, payType, payUrl } = res;

if (payType === 'qrcode') {
  // 直接展示，不要再自己生成二维码
  qrImg.src = payUrl;          // 二维码有效期 5 分钟
} else {
  // 手机端：直接跳转
  window.location.href = payUrl;
}
```

> 平台明确要求：**不能先显示二维码再跳 `payUrl`**，两者是互斥的两种形态。

## 三、接口二：查单（轮询）

```
GET /apiAI/user/xunhupay/query/{outTradeNo}
token: <登录 token>
```

`outTradeNo` 就是下单返回的订单号。

### 响应

```json
{
  "code": "0",
  "codeMsg": "成功",
  "data": "",
  "tradeState": "OD",
  "paid": true
}
```

| 字段 | 说明 |
| --- | --- |
| `tradeState` | `OD` 已支付 / `WP` 未支付 / `CD` 已取消 |
| `paid` | **是否已入账**，前端只需看这个 |

- `paid === true`：停止轮询，提示支付成功，刷新用户余额。
- `paid === false`：继续轮询。

### 轮询建议

- 间隔 **3–5 秒**（平台建议 5–10 秒，后端会实时查询上游）。
- 最长轮询 **10 分钟**，超时后提示二维码过期，引导重新下单。
- 页面切到后台再回来时立即查一次。

```js
let timer = setInterval(async () => {
  const r = await fetch(`/apiAI/user/xunhupay/query/${outTradeNo}`, {
    headers: { token },
  }).then((x) => x.json());

  if (r.code !== '0') stop();                 // 订单不存在等
  if (r.paid) { stop(); onPaid(); }
}, 4000);

setTimeout(stop, 10 * 60 * 1000);             // 10 分钟兜底
```

## 四、接口三：配置自检（运维/联调用）

```
GET /apiAI/user/xunhupay/status
```

```json
{ "code": "0", "configured": true, "gateway": "https://api.xunhupay.com/payment/do.html", "missing": [] }
```

`configured=false` 时 `missing` 会列出缺失的配置项，属于部署问题，前端只需提示「支付暂不可用」。

## 五、支付流程

### PC 扫码

```
前端下单 → 拿到 payUrl → <img> 展示二维码 → 每 4 秒查单
        → paid=true → 提示成功，刷新用户信息
```

### 手机 H5

```
前端下单 → location.href = payUrl
        → 用户在虎皮椒页面完成支付
        → 平台先通知后端，再让浏览器跳回 return_url（当前配置为站点首页）
        → 页面重新加载后，前端用 outTradeNo 查一次（或恢复轮询）确认 paid
```

> 手机端跳走再回来会刷新页面，**请把 `outTradeNo` 存到 `sessionStorage`/`localStorage`**，
> 回到页面后立刻查单确认结果。

## 六、错误码与处理

| HTTP | `code` / 场景 | 含义 | 前端处理 |
| --- | --- | --- | --- |
| 200 | `"0"` | 成功 | 正常处理 |
| 400 | `"4003"` 不支持的支付方式 | `pay_type` 传错 | 检查参数 |
| 400 | `"4003"` 支付金额必须是大于 0 的整数元 | 小数、0 或异常金额 | 前端限制为整数 |
| 502 | `"4003"` 虎皮椒下单失败 | 上游返回错误 | 提示稍后重试，可展示 `codeMsg` |
| 503 | `"4003"` 虎皮椒支付未配置 | 后端缺 AppID/Secret | 提示「支付暂不可用」 |
| 502 | `"3006"` 查询失败 | 查单上游异常 | 继续轮询或提示稍后重试 |
| 200 | `"3004"` 用户状态已过期 | token 失效 | 走登录过期逻辑 |

其余业务码沿用现有约定，`codeMsg` 可直接展示给用户。

## 七、金额规则（重要）

**系统没有会员档位，`token` 字段就是人民币余额。用户充多少，余额就加多少。**

| 前端传入 `money` | 后端行为 |
| --- | --- |
| 任意整数，如 1、26、50、88 | 等额入账：充 26 元，余额 +26 |
| 1.5 / 0.01 / 0 | 拒绝，返回 `400`，提示「支付金额必须是大于 0 的整数元」 |
| 负数 | 拒绝，返回 `422`（参数校验） |

- 金额就是实际支付金额，会原样写进支付二维码。
- 回调时后端会核对下单金额，不一致直接拒绝，不会入账。
- `function_code` 只用于订单号前缀和日志，不影响入账金额。

> 前端输入框建议：`type="number"` + `step="1"` + `min="1"`，并做整数校验。

## 八、联调清单

1. 后端 `.env` 已配好 `XUNHUPAY_APPID` / `XUNHUPAY_APPSECRET` / `XUNHUPAY_NOTIFY_URL`。
2. 后端 `/apiAI/user/xunhupay/status` 返回 `configured: true`。
3. 前端下单能拿到 `payUrl`，二维码能正常显示 / H5 能跳转。
4. 支付 1 元后，`/query/{outTradeNo}` 在几秒内返回 `paid: true`。
5. 支付回调地址必须公网可达：`https://www.rabbitj.top/apiAI/user/xunhupay/notify`。
6. 本地联调回调需内网穿透，把同一路径映射到本地端口。
